# Формальная семантика 2D-грамматики

Документ фиксирует, **что означает грамматика**, независимо от того, как её ищет матчер.
Всё, что компилятор (`src/vstuxls/grammar2d/compiler`) доказывает или проверяет, опирается на эти определения.

## 1. Объекты

* **Сетка** — прямоугольная таблица клеток, часть клеток объединена в прямоугольные блоки.
* **Рамка** (box) — прямоугольник по линиям сетки: `left < right`, `top < bottom`; ширина `w = right − left`
  (число клеток), высота `h = bottom − top`. Рамка — это **два интервала** (по x и по y).
* **Совпадение** (match) паттерна `P` — пара «рамка + дерево разбора»: каждому обязательному компоненту
  сопоставлено совпадение его паттерна.
* **Семантика грамматики** — *множество всех согласованных разборов* (all consistent parses).
  Выбор подмножества («лучшие», непересекающиеся, покрывающие) — отдельный слой, **политика** (раздел 5).
  Это принципиально: структура грамматики описывает *что может быть*, политика — *что мы предпочитаем*.

## 2. Виды паттернов

| kind | смысл |
|------|-------|
| `cell` | блок клеток, содержимое которого имеет тип `content_type` (см. `cell_types`) |
| `area` | прямоугольник с компонентами; рамка = объемлющий прямоугольник **внутренних** (`inner`) компонентов |
| `array` | последовательность ≥ `item_count` элементов одного паттерна вдоль `direction` с промежутками `gap` |
| `array_in_context` | то же, но границы массива задаются контекстом |
| `alt` / `one_of` | объединение альтернатив (чистый выбор, без собственной геометрии) |
| `general` | абстрактный паттерн: совпадает, если совпал любой из паттернов, его расширяющих (`extends`) |

`extends` — отношение «является разновидностью»: совпадение `Child` является совпадением `Base`.
Это *не* копирование полей, поэтому `general + extends` — это альтернатива; в v2 для этого есть `alt`.

## 3. Геометрические ограничения

Рёбра рамки: `left, right, top, bottom` (линии сетки). Для компонента `C` внутри `P`:

* **padding** (`inner`-компоненты): расстояние от ребра `P` до одноимённого ребра `C`
  (`left`/`top`: `C.e − P.e ∈ R`; `right`/`bottom`: `P.e − C.e ∈ R`). По умолчанию `0+` (внутри, без выхода за рамку).
* **margin** (`outer`-компоненты): расстояние от ребра `P` до *противоположного* ребра `C`
  (компонент снаружи). По умолчанию не ограничено.
* **size**: `w ∈ R` и/или `h ∈ R` для рамки.
* **relations** (v2): `A.edge ⋈ B.edge + k`, `A.edge − B.edge in a..b`.
* **массив**: `gap` — число *пустых клеток* между соседними элементами
  (`next.left − prev.right = gap` при `direction: row`).

Все эти условия — **разностные ограничения** `x_i − x_j ≤ c` над координатами рёбер.
Оси x и y независимы, поэтому каждый паттерн даёт две Simple Temporal Networks (STN):
согласованность — отсутствие отрицательных циклов (Беллман–Форд / Флойд–Уоршелл). Это даёт:

* доказательство **противоречий** (с выводом цикла — «свидетеля»);
* **неявные границы** (кратчайшие пути): реальные min/max размеры и расстояния;
* **избыточные** ограничения (выводимые из остальных).

Нюанс корректности: `P.рамка = объемлющий прямоугольник внутренних компонентов` в STN **не** моделируется
(это min/max, не разностное ограничение). Моделируются только `P.e ≤/≥ C.e`. Следовательно анализ — *релаксация*:
если релаксация противоречива, то противоречива и грамматика (отчёт ERROR); обратное не утверждается.

## 4. Лексическая часть

Тип ячейки — регулярное выражение(я) над текстом клетки (плюс `except`, `priority`).
Два типа **пересекаются**, если существует строка, подходящая обоим; конфликт разрешается:
явным `priority` / `except` либо (устаревший способ) вручную написанным lookahead в регулярке.
Компилятор ищет пересечения и показывает свидетель-строку.

## 5. Политика (отдельный слой)

Политика не влияет на *множество* разборов, только на выбор из него:

* `confidence`, `precision_threshold` — оценка качества совпадения;
* `overlap` — как разрешать пересекающиеся кандидаты одного паттерна (`none | full | partial`, метрика, порядок);
* `exclusive` (бывший `allows_overlapping: false` инвертирован) — исключать ли конкурирующих кандидатов;
* `priority`, `prefer` — предпочтение между альтернативами, а не «хаки через вес»;
* `cost` — штраф/бонус в глобальной оптимизации.

Политику можно вынести из паттернов в корневой раздел `policies:` — структура грамматики остаётся чистой.

## 6. Что запрещено (диагностики)

Каждая проблема имеет код (`G…` — структура, `GEO…` — геометрия, `LEX…` — лексика, `AMB…` — неоднозначность,
`POL…` — политика, `COV…` — покрытие). Таблица кодов — `compiler/diagnostics.py::CODES`.
Принцип: *ничего не молчит* — старые `print('SYNTAX WARN')`, `None` для неизвестного kind и т. п.
заменены диагностиками с `файл:строка`.

## 7. Конвейер

```
YAML (v1 / v2)  →  frontend (+позиции)  →  шаблоны/desugar  →  IR

                                                              ├─ geometry/STN  (GEO…)
                                                              ├─ celltypes     (LEX…)
                                                              ├─ ambiguity     (AMB…, POL…)
                                                              └─ planner → matcher → selection
```
